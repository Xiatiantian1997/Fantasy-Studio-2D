# 幻真画室｜软件产品方案 v0.1

> **定位已定：自己做一套面向普通用户的本地视觉创作软件**。保留 ComfyUI、Blender 等成熟底层；**不让用户直接面对节点图、Rig 权重或专业建模面板**。
>
> 本文件是下一版产品设计，不代表功能已经实现。v1 当前实现：文生图、整图 img2img、切换 checkpoint、一个 LoRA、保存和停止。尚无 ControlNet、蒙版修复、3D、图生文、素材检索或 AI 自主审图。

## 1. 最重要的产品决策

- **最终只有一个主要用户入口：「幻真画室」**：一个简洁中文界面，提供 2D 绘画、3D 人体参考、素材、作品管理。
- **代码与生产流程仍分两个 GitHub 仓库**：
  - [Fantasy-Studio-2D](https://github.com/Xiatiantian1997/Fantasy-Studio-2D) —— **主程序 / 用户界面 / 作画编排**。
  - [Fantasy-Studio-3D](https://github.com/Xiatiantian1997/Fantasy-Studio-3D) —— **Blender 模型与姿势 / 相机 / 深度 / 法线 / 骨架控制包**。
  - [body](https://github.com/Xiatiantian1997/body) —— 原有人脸研究，独立保留，未迁移。
- **不是从零重写绘图引擎**。ComfyUI 仍是生成后端，Blender 仍是三维编辑/导出工具；我们自己做统一操作层。
- **优先 Windows PC**。先用本地启动器 + 浏览器 UI 验证，等实际可用后再评估封装为 Windows 桌面应用（exe/安装包）。**“自研软件”不等于马上有 exe**。

## 2. 用户能看到的界面

首页只显示四个主入口：

| 主入口 | 用户需要做什么 | 软件做什么 |
| --- | --- | --- |
| **2D 绘画** | 选择画风、人物、姿势，输入描述，点生成 | 组装 ComfyUI 工作流、保存配方和图像 |
| **3D 人体** | 选基础人体、姿势、视角，旋转查看、导出 | 调用 3D 模块，生成结构控制包 |
| **素材库** | 按人物、姿态、服装、材质、画风检索 | 统一索引、标注来源和使用权限 |
| **作品** | 比较、保存、继续修改 | 版本历史、生成参数、局部编辑入口 |

常用操作直接展示；专业参数放「高级设置」，无需理解节点名称。首次启动后建议直接进入 2D 绘画，不出现开发者工作流画布。

操作方式有两种，**不复制同一个素材库**：
- **AI 辅助创作**：代理只通过限制权限的本地 API 操作已允许访问的素材和任务，可请求用户复核。
- **手动创作**：用户自己选择模型、工作流、素材及保存位置；不等于放开 AI 助手适用的限制。
- 权限由服务端/磁盘目录实现，而非靠隐藏前端按钮；私人原档不进入默认 AI 模式。

## 3. 画风与模型

第一优先级固定 **三种插画画风**：
1. **幻真动漫**：高精动漫、明显的二维美型和立体渐变。
2. **半写实插画**：保留绘画感，增加真实体积、光影与材质。
3. **数字油画**：大色块、边缘虚实、笔触层次，而不是给光滑图片加滤镜。

**真人写真**保留为可选实验模式，晚于三种插画画风落地；暂不要求用户会建模。

“风格配方”必须记录 checkpoint、LoRA、参考图 ID、参考权重、提示词、负面词、随机种子、采样器、步数、画幅与处理步骤。相同文字提示词不保证相同画风；模型/参考/工作流测试之后才能提供默认配方。

## 4. 2D 与 3D 如何连接

**采用文件接口，先不做紧耦合服务**：

```text
3D 仓库（Blender / Rig / 姿势 / 相机）
                  |
                  v
导出 manifest.json + RGB + Depth + Normal + Pose
                  |
                  v
2D 主程序：验证版本、来源、相机和文件，再转成适配的 ControlNet 输入
                  |
                  v
ComfyUI 本地生成 → 预览 → 用户复核 → 保存版本
```

具体接口见 [3D 导出协议](https://github.com/Xiatiantian1997/Fantasy-Studio-3D/blob/main/docs/interface-v0.1.md)。**2D v1 没有读取此格式的功能。**

3D 专业调整初期继续在 Blender 中完成；完成模型和导出验证后，才开发简化查看/选姿势界面。不要提前承诺任何体型、任意姿势都不会穿模。

## 5. 模块边界与长期资源

```text
D:\AI\FantasyStudio\                  # 仅作为推荐本地目录
  studio-2d/                           # 主程序与 Web UI
  studio-3d/                           # 3D 工程和 Blender scripts
  models/                              # 模型权重；不放 Github
  materials/
    originals/                         # 原图，不覆盖
    curated/                           # 可用于创作的精选参考
    private/                           # 仅用户手动管理的私人库
  exports/                             # 3D 结构参考包
  outputs/                             # 2D 图像与版本
  cache/                               # 缓存和临时文件
```

原图/授权信息和衍生图保持来源关联。GitHub 只放代码与安全的示例。默认仅监听 127.0.0.1；将来局域网使用需认证与访问控制，不把 ComfyUI 直接公开到公网。

## 6. 最小交付顺序

| 阶段 | 做到怎样才算完成 |
| --- | --- |
| A. 保住 v1 | 在用户 Windows + 3060 Ti 上安装并真实出图，现有操作不回退 |
| B. 统一 UI | 2D/3D/素材/作品入口跑通；操作能触发对应真实功能，未实现的禁用并说明 |
| C. 三画风 | 同一原创成年角色与构图三套配方，能被保存、复现、对比 |
| D. 2D 控制 | 姿势或参考图控制至少一套可用，修正蒙版、图生文逐步添加 |
| E. 3D 接口 | 真实 Blender 姿势/相机导出并通过 schema、像素、ControlNet 实测 |
| F. 一体化体验 | 2D 界面选择 3D 姿势并生成作品；是否打包 exe 再评估 |

**本次更新的范围**：只落实产品方案、仓库协作和可交互静态界面原型。未改变 v1 的运行代码、模型或安装器。

## 7. 给 Grok/另一位 AI 的协作原则

- **先验证再宣称**：原型、真实前端、Blender 插件、ComfyUI 生成分别标记完成状态。
- 优先修复人体/衣服形变与视角一致性，不为复杂 UI 牺牲实际质量。
- 私人敏感素材在本地独立处理，不自动上传公开 GitHub 或第三方模型服务。
- 统一输出标准格式（PNG/WebP/GLB/JSON/EXR），版本字段明确。
- 与 `body` 人脸旧工程保持独立，不直接覆盖已有确认模型。
