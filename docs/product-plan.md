# 幻真画室｜统一产品方案

## 唯一产品

用户只有**一套「幻真画室」**。以前已完成的 2D 功能继续扩展，不做“旧版/新版”并行产品，也不要求重复安装。

代码仍按实现职责分工：
- Fantasy-Studio-2D：**唯一软件入口**、Web UI、ComfyUI 编排、素材检索与作品管理。
- Fantasy-Studio-3D：Blender 人体工程、Rig、姿势、深度/法线和姿态导出。
- body：既有人脸研究，作为资料和可选来源，不能当做另一个版本的主软件。

独立仓库 ≠ 独立应用。用户可在 2D/3D/素材/作品四个入口切换，内部实现由软件负责。

## 设计原则

1. **简约而不简单**：默认只给人物、画风、姿势、生成按钮；高级参数按需出现。
2. **底层成熟**：用 ComfyUI 生成、Blender 建模和导出，不从零造绘图/建模引擎。
3. **现有功能继续使用**：文生图、整图参考重绘、模型/LoRA、参数、预览保存必须保留。
4. **严格区分已完成与计划**：导航的存在不代表 3D 模型、ControlNet 或素材数据库已实现。
5. **私人数据隔离**：AI 代理通过受限后端访问精选参考；用户独立管理完整本地资料。不要把私有图库提交公开 GitHub。
6. **一个安装路径**：优先非 C 盘，未来 3D 组件和素材库可以在同一软件内按需安装/配置。

## 功能与实际状态

| 入口 | 现有可用基础 | 以后接入 |
| --- | --- | --- |
| 2D 绘画 | 已写代码：文生图、img2img、基本模型/LoRA、保存/停止 | 幻真动漫、半写实插画、数字油画的真实配方；局部重绘、姿势 |
| 3D 人体 | 主界面有“规划中”页面 | Blender Rig、五姿势、视角、RGB/Depth/Normal/Pose 控制图 |
| 素材库 | 主界面有“规划中”页面；2D 可直接上传参考图 | SQLite 检索、来源、标签、图生文、权限管理 |
| 作品 | 当前在 2D 预览和保存图片 | 历史版本、配方、人物一致性与对照评估 |

当前所有功能均未在用户 Windows RTX 3060 Ti 上完整通过实际 GPU 测试，因此不作实机已完成声明。

## 画风

固定优先验证三种 2D 画风：
- **幻真动漫**：2D 人物美型 + 立体上色，不退化成普通真人脸。
- **半写实插画**：更自然的体积、皮肤和阴影，仍有插画语言。
- **数字油画**：绘画笔触、虚实边缘、色块组织。

风格配方需固定基础模型、LoRA、参考类型与强度、提示词、采样、种子和生成尺寸，进行同角色对照测试；只是把按钮命名为风格并不能证明模型能完成。

## 3D 的实施顺序

1. 先在 Blender 验证高质量、合法来源的带 Rig 成年人体基础模型。
2. 锁定体型，测试站立、侧身、坐姿、抬手和跪姿；针对实际形变问题修正。
3. 同一相机、同一帧导出 RGB、Depth、Normal、姿态关键点及 JSON manifest。
4. 在 2D 程序中添加兼容的 ControlNet 使用流程并验证。
5. 通过真实模型和导出验证后，才把查看和简化动作操作接入同一个主界面。

3D 输出规格维护于 Fantasy-Studio-3D/docs/interface-v0.1.md。此处版本号只是**内部数据接口兼容标识**，不是第二个应用版本。

## 工程迁移与保存

目前已把“2D/3D/素材/作品”导航直接加进 **app/web/index.html**：它仍是唯一运行入口。原先的独立 prototypes/studio-shell.html 仅为视觉设计存档，不作第二套界面维护。

保留已写代码和测试，不重开一套源代码；兼容旧目录内的 LocalStudio 字符串只是内部标识，未来有实机迁移测试后再考虑统一底层命名。

建议 D:\AI\FantasyStudio\ 放主程序、3D 模块、models、materials、outputs、exports。GitHub 仅保存代码及可公开的规范。
